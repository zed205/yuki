# Multi-Agent Architecture: Orchestrator-Worker Pattern

## Overview
This document outlines the architectural strategy for implementing a multi-agent system within the AI agent application. The system utilizes a **"Heavy" model** (e.g., Yuki/Large LLM) for complex reasoning, and a **"Lite" model** (e.g., Phi-3, Llama-3-8B) for specialized, efficient, and mundane tasks. This "Orchestrator-Worker" pattern optimizes latency, cost, and context management.

## Architecture Components
- **Orchestrator (Heavy Model):** Responsible for high-level reasoning, conversation management, and primary user interaction.
- **Worker (Lite Model):** Responsible for specialized sub-tasks: Compaction, Fact-Checking, and Parsing.

## Specialized Task Implementations

### 1. Smart Compaction (Context Janitor)
**Objective:** Prevent context window overflow and maintain long-term conversation continuity.
**Mechanism:**
- Triggered periodically based on token count thresholds.
- The Lite Model generates a condensed summary of the conversation history (key facts, decisions, current state).
- The original long history is replaced in the context buffer with the summary, prefixed with a `[SYSTEM_SUMMARY]` marker.
**Benefit:** Maximizes effective context window usage and prevents "context drift."

### 2. Fact-Checking (Critical Auditor)
**Objective:** Ensure the accuracy of high-criticality or complex information.
**Mechanism:**
- Intercept the Heavy Model's output before it is displayed to the user.
- The claim and the relevant source data are sent to the Lite Model.
- The Lite Model's verification (e.g., `[VERIFIED]` or `[DISCREPANCY: Reason]`) is injected into the chat history.
**Benefit:** Provides a layer of automated verification and improves system reliability.

### 3. Information Parsing (Data Miner)
**Objective:** Extract specific facts from large documents without overwhelming the Heavy Model's context.
**Mechanism:**
- Large documents are processed by the Lite Model before being passed to the Orchestrator.
- The Lite Model extracts specific data points into a structured format (e.g., JSON).
- Only the structured JSON is injected into the Heavy Model's context.
**Benefit:** Dramatically increases signal-to-noise ratio and reduces token costs.

## Communication & Chat Template Strategies

| Strategy | Best Use Case | Implementation Detail |
| :--- | :--- | :--- |
| **Tool/Function Calling** | Fact-Checking | Treat Lite Model output as a `tool_result` in the message history. |
| **Role-Prefixing** | General Sub-tasks | Use explicit delimiters like `>>> [LITE_MODEL_OUTPUT]: ... >>>` to distinguish from User/Assistant. |
| **Context Injection** | Compaction & Parsing | Inject summarized text or JSON directly into the `system` or `user` message roles. |
